# tP Feature Workflow

Use this workflow for a concrete request to start, implement, or publish a tP feature, fix, enhancement, or project task. A direct request such as “Add search,” “Implement search,” “Rename the skill files,” or “Push these uncommitted feature changes” is enough to invoke it. Inspect the changes when a Git request does not identify the deliverable. Do not invoke it for speculative discussion, planning, an idea explicitly deferred to later, or Git maintenance unrelated to a concrete deliverable.

Before any workflow investigation or mutation, tell the user that you are starting the tP workflow and what you expect to create, naming the likely issue(s) and branch(es) or explaining what information is not yet known. Wait for the user's explicit confirmation before proceeding. A request to implement the feature does not replace this confirmation.

Read [the workflow procedure](references/workflow.md) and follow it. Follow the current repository `AGENTS.md` and applicable project instructions for implementation, testing, documentation, commits, and verification. The workflow procedure does not grant permission to merge a PR, release, edit milestone deadlines, or close an iteration.
